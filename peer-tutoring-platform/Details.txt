================================================================================
                              APPLICATION OVERVIEW
================================================================================

The Peer Tutoring Marketplace Platform is a comprehensive web application that
connects students with peer tutors for personalized learning sessions. The
platform facilitates tutor discovery, session booking, payment tracking, and
rating systems with role-based access for Students, Tutors, and Administrators.

KEY OBJECTIVES
--------------
1. Enable students to find and book tutoring sessions with verified peer tutors
2. Allow tutors to create sessions, manage bookings, and track earnings
3. Provide administrators with tools for moderation, approvals, and analytics
4. Implement a secure authentication system with role-based access control
5. Create a rating system to maintain quality standards

================================================================================
                         CORE FUNCTIONALITY
================================================================================

1. USER AUTHENTICATION & REGISTRATION
-------------------------------------
- User registration with email, password, name, phone number
- Role selection during registration (Student/Tutor/Admin)
- JWT-based login with token storage in localStorage
- Protected routes based on user roles
- Password encryption using BCrypt

Endpoints:
  POST /api/auth/register    - Register new user
  POST /api/auth/login       - Authenticate user
  GET  /api/auth/me          - Get current user details

2. USER ROLES & PERMISSIONS
---------------------------
STUDENT:
  - Browse approved tutor profiles
  - Search tutors by subject
  - View available tutoring sessions
  - Book sessions
  - View booking history
  - Submit ratings and reviews for completed sessions

TUTOR:
  - Create and manage tutor profile (requires admin approval)
  - Create tutoring sessions with details (title, subject, time, price)
  - View and manage bookings for their sessions
  - Confirm or reject booking requests
  - Mark sessions as completed
  - View earnings and ratings

ADMIN:
  - View dashboard statistics
  - Approve or reject tutor profiles
  - View all users, sessions, and bookings
  - Process payouts to tutors
  - Moderate platform content

3. TUTOR PROFILE MANAGEMENT
---------------------------
- Tutors create profiles with bio, subject expertise, hourly rate
- Profile status: PENDING → APPROVED/REJECTED
- Approved profiles are visible to students
- Average rating calculation based on student feedback
- Total sessions count tracking

Endpoints:
  POST /api/tutor/profile              - Create tutor profile
  GET  /api/tutors                     - List approved tutors
  GET  /api/tutors/search              - Search tutors by subject
  POST /api/admin/tutors/{id}/approve  - Approve tutor (Admin)
  POST /api/admin/tutors/{id}/reject   - Reject tutor (Admin)

4. SESSION MANAGEMENT
---------------------
- Tutors create sessions with:
  * Title and description
  * Subject category
  * Start and end time
  * Price per session
  * Maximum students capacity
- Session types: INDIVIDUAL or GROUP
- Session status: AVAILABLE, FULL, COMPLETED, CANCELLED
- Conflict prevention for overlapping sessions

Endpoints:
  GET    /api/sessions              - List all sessions
  GET    /api/sessions/available    - List available sessions
  POST   /api/sessions              - Create session (Tutor)
  PUT    /api/sessions/{id}         - Update session (Tutor)
  DELETE /api/sessions/{id}         - Delete session (Tutor)

5. BOOKING SYSTEM
-----------------
Workflow: REQUESTED → CONFIRMED/REJECTED → COMPLETED

Features:
  - Students request bookings for available sessions
  - Tutors confirm or reject booking requests
  - Confirmed bookings mark sessions as filled
  - Tutors mark completed sessions
  - Payment status tracking (PENDING, PAID, REFUNDED)
  - Automatic validation prevents double-booking

Endpoints:
  GET   /api/student/bookings             - View my bookings (Student)
  POST  /api/student/bookings             - Create booking (Student)
  POST  /api/tutor/bookings/{id}/confirm   - Confirm booking (Tutor)
  POST  /api/tutor/bookings/{id}/reject    - Reject booking (Tutor)
  POST  /api/tutor/bookings/{id}/complete  - Mark complete (Tutor)
  POST  /api/tutor/bookings/{id}/cancel    - Cancel booking (Tutor)

6. RATING & REVIEW SYSTEM
-------------------------
- Students submit ratings (1-5 stars) and reviews after completed sessions
- Ratings are linked to specific bookings to prevent duplicate reviews
- Tutor profiles display average rating
- Reviews can be marked as visible/hidden by admin

Endpoints:
  POST /api/student/ratings    - Submit rating (Student)
  GET  /api/tutor/ratings      - View tutor ratings

7. ADMIN DASHBOARD & PAYOUTS
----------------------------
- Dashboard statistics:
  * Total users, tutors, sessions, bookings
  * Pending tutor approvals count
  * Recent bookings overview

- Payout Management:
  * Process payments to tutors
  * Track payout status: PENDING, PROCESSING, COMPLETED, FAILED
  * Payment method tracking
  * Transaction ID recording
  * Processed by admin tracking

Endpoints:
  GET  /api/admin/dashboard          - Get statistics
  GET  /api/admin/tutors/pending     - List pending tutor approvals
  GET  /api/admin/bookings           - List all bookings
  POST /api/admin/payouts            - Create payout
  GET  /api/admin/payouts            - List all payouts

================================================================================
                          DATABASE SCHEMA
================================================================================

ENTITIES & RELATIONSHIPS
------------------------

1. USER
   - id, email, password, firstName, lastName, phoneNumber
   - role (STUDENT, TUTOR, ADMIN), active, verified

2. TUTOR_PROFILE (1:1 with USER)
   - id, user_id (FK), bio, subject, hourlyRate
   - status (PENDING, APPROVED, REJECTED)
   - averageRating, totalSessions

3. SESSION (N:1 with USER - Tutor)
   - id, tutor_id (FK), title, description, subject
   - startTime, endTime, price, maxStudents
   - enrolled (count), type (INDIVIDUAL, GROUP), status

4. BOOKING (N:1 with USER - Student, N:1 with SESSION)
   - id, student_id (FK), session_id (FK), amount, notes
   - status (REQUESTED, CONFIRMED, REJECTED, CANCELLED, COMPLETED)
   - paymentStatus (PENDING, PAID, REFUNDED)
   - createdAt, confirmedAt, cancelledAt, completedAt

5. RATING (1:1 with BOOKING)
   - id, booking_id (FK), student_id (FK), tutor_id (FK)
   - rating (1-5), review, visible

6. PAYOUT (N:1 with USER - Tutor)
   - id, tutor_id (FK), processed_by (FK - Admin)
   - amount, currency, status
   - paymentMethod, transactionId, notes, processedAt

================================================================================
                        SECURITY IMPLEMENTATION
================================================================================

1. JWT Authentication Flow:
   - User submits credentials to /api/auth/login
   - Server validates credentials and generates JWT token
   - Token contains user ID, email, and role
   - Token expires after 24 hours
   - Client stores token in localStorage
   - Token sent in Authorization header for protected requests

2. Role-Based Access Control:
   - @PreAuthorize annotations on controller methods
   - Method-level security checks
   - Role hierarchy: ADMIN > TUTOR > STUDENT

3. Data Protection:
   - BCrypt password hashing (strength 10)
   - CORS configuration restricting origins
   - Input validation using @Valid annotations
   - SQL injection prevention via JPA/Hibernate
   - XSS protection through proper output encoding

4. API Security:
   - JWT filter validates tokens before request processing
   - Stateless authentication (no server-side sessions)
   - Secure endpoints based on user roles
